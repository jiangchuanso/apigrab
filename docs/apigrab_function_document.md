# 接口数据采集入库工具ApiGrab

> 文档说明：本文档描述「接口数据采集入库系统（API Grab）」的总体定位、功能细节、系统架构与技术栈，以及当前遗留事项。

---

## 一、总体介绍

### 1.1 系统定位

API Grab 是一套通用的「接口数据采集入库」平台。它通过配置化的方式对接各类 RESTful API（JSON / XML / NDJSON 响应），按需拉取数据、解析、转换清洗，并将结果按指定策略写入目标数据库，同时提供任务调度、执行监控与失败告警能力。

系统面向企业数据集成场景中普遍存在的痛点：异构数据源接口协议、认证方式、分页方式各异，目标库类型多样，采集过程缺乏可观测性与稳定性保障。

### 1.2 系统目标

- **配置化采集**：不写代码即可完成接口接入、分页拉取、字段映射与目标库写入。
- **多认证适配**：支持无认证、Basic、Bearer、OAuth2、自定义 Header、账号密码换 Token 等多种认证方式，并支持认证配置在多接口间复用。
- **多数据库写入**：运行期动态管理 MySQL / Oracle / SQL Server / PostgreSQL 及达梦、人大金仓、神通、GBase8A、瀚高、openGauss、OceanBase、优炫 UXDB 等国产库目标数据源，支持自动建表与多写入模式。
- **可观测执行**：采集过程分阶段记录进度、统计与失败样本，支持执行历史回溯与入库数据预览。
- **稳定容错**：支持失败重试、执行超时、按批写入、分页节流、失败告警与部分成功统计。
- **灵活转换**：支持字段映射与内置转换函数，并支持 Groovy 脚本完成复杂数据清洗与聚合。

### 1.3 用户角色

| 角色 | 说明 | 主要权限 |
|------|------|----------|
| 管理员（ADMIN） | 系统管理用户 | 全部功能，含用户管理 |
| 普通用户（USER） | 业务使用用户 | 数据源、认证配置、接口配置、采集任务、监控、告警等；无用户管理权限 |

系统内置默认管理员账号（首次启动、用户表为空时自动创建 `admin / 123456`，权限为 ADMIN、状态启用）。

### 1.4 运行形态

- 后端：单体 Spring Boot 应用，提供 REST API 与 Quartz 调度，元数据存于 MySQL。
- 前端：Vue 单页应用，通过 `/api` 前缀访问后端。
- 目标库：由系统在运行期动态注册与使用，与元数据库相互独立。

## 二、系统功能

### 2.1 用户认证与权限管理

**功能点：**

1. **登录**：用户名 + 密码登录，密码采用 BCrypt 校验；登录成功后签发不透明访问令牌（默认有效期 7200 秒，访问时滑动续期）。
2. **登出**：注销当前令牌。
3. **当前用户信息**：获取登录用户资料（用户名、真实姓名、角色等）。
4. **个人资料**：修改真实姓名、邮箱、地址等个人资料。
5. **修改密码**：校验旧密码后设置新密码。
6. **用户管理（仅管理员）**：用户列表（按用户名、角色、状态筛选）、新增、编辑、重置密码、启用/禁用、删除。
7. **访问控制**：除登录接口外，所有 `/api/**` 均需携带令牌；未登录或令牌失效返回 401，越权访问用户管理返回 403。
8. **安全约束**：
   - 不能删除或禁用当前登录用户本人；
   - 不能删除、禁用或降级「最后一个启用状态的管理员」；
   - 禁用用户时同时清除该用户所有令牌；
   - 任何接口响应中都不包含密码字段；
   - 新用户密码、重置密码最少 6 位。
9. **登录记忆**：登录页可勾选「记住用户名」（仅记忆用户名，不保存密码）。

### 2.2 数据源管理

**功能点：**

1. **数据源列表**：展示名称、数据库类型、JDBC URL、用户名、最大连接数、引用任务数；支持分页。
2. **新增/编辑数据源**：配置名称、数据库类型、JDBC URL、驱动类（按类型自动填充）、数据库版本（Oracle / 国产库可见）、用户名、密码、外部驱动路径、连接池最大连接数、最小空闲数、备注。
3. **数据库类型**：MySQL / Oracle / SQL Server / PostgreSQL，以及达梦 DM、人大金仓 KingbaseES、神通 Oscar、南大通用 GBase8A、瀚高 HighGo、openGauss、OceanBase、优炫 UXDB。清单由后端 `DbType` 枚举经 `/api/datasource-meta/db-types` 下发，选择类型后自动填充驱动类与 JDBC URL 模板，自动建表、写入、预览、探活、元数据查询均按方言族适配。
4. **测试连接**：新增时可直接用当前表单值测试（无需先保存）；编辑时可测试已保存的数据源连接。
5. **删除保护**：被任一采集任务引用的数据源不允许删除（列表中对引用数大于 0 的行禁用删除按钮并提示）。
6. **元数据级联浏览**：按「库/模式 → 表/视图 → 列」层级获取目标库结构，供任务配置使用：
   - 库/模式：MySQL / GBase8A / OceanBase 对应 database，PostgreSQL 系国产库对应 schema，Oracle / 达梦对应用户/模式，SQL Server 对应 schema；
   - 表：返回表与视图；
   - 列：返回列名、类型、长度、是否可空、备注以及**是否为主键**。
7. **连接池管理**：目标库连接池按需（首次使用）创建与缓存，配置变更或删除后失效并重建，应用启动不依赖任何目标库可达。
8. **密码存储**：数据源密码加密存储，运行期解密使用。
9. **外部驱动加载**：国产库驱动为厂商私有 jar，不进入 Maven classpath。按 `drivers/<类型名小写>/<版本>/*.jar` 放置后，由 `/api/datasource-meta/drivers` 扫描列出，数据源的 `driverPath`（单个 jar、目录或多个路径逗号分隔）指定的驱动经隔离 `URLClassLoader` 加载；同一版本目录下的多个 jar 一并加载，不同库/版本互不冲突。

### 2.3 认证配置管理

认证配置独立管理，可被多个接口配置共享引用。

**功能点：**

1. **认证配置列表**：展示名称、类型、引用数；支持按名称模糊、按类型筛选、分页。名称全局唯一（忽略大小写与首尾空格）。
2. **新增/编辑认证配置**：配置名称、认证类型、状态、备注；不同类型展示不同参数。
3. **认证类型与参数**：

   | 类型 | 说明 | 主要参数 |
   |------|------|----------|
   | Basic Auth | HTTP Basic 认证 | 用户名、密码 |
   | Bearer Token | 静态令牌 | Token |
   | OAuth2 Client Credentials | 客户端凭证模式获取令牌 | Token URL、Client ID、Client Secret、Scope（可选）、Token 提取路径（默认 `$.access_token`）、过期时间（秒，缺省按响应 `expires_in`，再缺省 3600） |
   | 自定义 Header | 自定义请求头 | 任意键值对（空键忽略） |
   | 账号密码换 Token | 用账号密码换取令牌 | Token URL、请求体格式（FORM/JSON）、请求体字段（键值对）、Token 提取路径、过期时间、Token 放置位置（HEADER/QUERY/BODY）、Token 键名（默认 `Authorization`）、Token 值格式（必须含 `{token}`，如 `Bearer {token}`） |

4. **测试获取 Token**：仅 OAuth2 与「账号密码换 Token」提供。可发起真实取 Token 请求，展示原始响应结构，支持在响应结构树中点选节点自动填充「Token 提取路径」，并支持「用当前路径重新测试」。
5. **令牌缓存与续期**：OAuth2 与账号密码换 Token 的令牌按认证配置缓存，按过期时间（提前约 60 秒）自动刷新。
6. **删除保护**：被任一接口配置引用的认证配置不允许删除。
7. **敏感信息**：密码、令牌、Client Secret 等以配置形式保存，接口响应中按需遮蔽展示。

### 2.4 接口配置管理

接口配置描述「从哪里、用什么方式、如何认证、怎样翻页、如何解析」的完整采集入口。

**功能点：**

1. **接口配置列表**：展示名称、URL、请求方法、认证（认证配置名或「无认证」）、是否分页、引用任务数；支持按名称模糊搜索、分页。名称全局唯一。
2. **基本信息**：接口名称（必填、≤100 字符）、请求方法（界面提供 GET / POST）、接口 URL（必填）。
3. **URL 查询串归一**：在 URL 输入框失焦或回车时，自动将 URL 内联的查询串提取到「查询参数」区域并从 URL 中移除，查询参数区域成为唯一来源。
4. **请求头**：键值对编辑，提供常用预设（Content-Type、Accept、User-Agent、Cache-Control），不提供 Authorization（由认证配置生成），避免重复头。
5. **查询参数**：键值对编辑。
6. **请求体**（非 GET 时）：
   - 请求体类型：NONE / JSON / FORM / XML；
   - FORM：以键值对编辑；
   - JSON / XML：文本编辑，失焦校验格式（JSON 语法、XML 良构），非法内容阻止保存与试跑，空内容允许；XML 以 `application/xml; charset=utf-8` 发送。
7. **超时配置**：连接超时、读取超时（单位秒，界面默认 10 / 60，留空或非正值按默认生效）。
8. **认证关联**：从共享认证配置中选择一个，或选择「无认证」（为空即无认证）。
9. **分页配置**：见 2.4.1。
10. **数据转换模式**：字段映射模式 / Groovy 脚本模式；Groovy 脚本编辑器提供脚本模板、变量说明与「脚本调试」（需先保存接口配置，输入样例数据执行并预览输出）。
11. **响应配置**：见 2.4.2。
12. **详情补全**：见 2.4.3。
13. **在线测试（试跑）**：支持对未保存的临时配置或已保存配置发起真实请求；成功时缓存首条解析记录作为「样例数据」，失败不覆盖既有样例。
14. **删除保护**：被任一采集任务引用的接口配置不允许删除。

#### 2.4.1 分页配置

- **启用分页**：开关控制。
- **分页模式**：
  - PAGE_NUMBER（页码翻页）：页号参数（默认 `page`）、每页条数参数（默认 `size`）；
  - OFFSET（偏移翻页）：偏移参数（默认 `offset`）、上限参数（默认 `limit`）；
  - CURSOR（游标翻页）：游标参数（默认 `cursor`）、下一页游标路径（默认 `$.next_cursor`）、初始游标（留空从首次请求开始）。
- **参数位置**：QUERY（查询串）/ BODY（请求体）/ PATH（URL 路径）。
  - 公共规则：参数名在请求头 / 查询参数 / 请求体中以 `${参数名}` 出现时优先替换，已占位的参数不再重复注入。
  - PATH：额外把 URL 中的 `${参数名}` 替换为当前页取值（如 `/list/${page}/${size}`），按原值替换、不做 URL 编码；URL 中未占位的参数退化为查询参数追加。
  - BODY：复用同一套参数名作为请求体键名，注入方式随请求体类型不同（JSON 合并顶层键、FORM 追加表单键、XML 按元素名替换或追加；NONE 时明确报错）。
  - FORM 请求体：正文按 `application/x-www-form-urlencoded` 编码串处理，替换前先逐段解码，因此 `${参数名}` 无论原样书写还是已按表单编码（如 `%24%7Bpage%7D`）都能命中；注入的键/值按表单规则编码，其中的 `&`、`=`、`+`、`%` 不会破坏报文分隔。
- **批量与终止条件**（游标模式外可见）：
  - 每页条数（默认 50，范围 1–10000）；
  - 总页数（0 表示不限，大于 0 时按总页数终止，优先级最高）；
  - 按批大小停止（当前页返回条数少于每页条数时停止，默认开启）。
- **通用项**：请求间隔（毫秒，默认 0，用于分页节流）、最大页数（安全上限，默认 99999）。
- **条件显示**：不同分页模式只显示相关参数；切换模式不清空隐藏项的值。

#### 2.4.2 响应配置

- **响应类型**：JSON / XML，可自动检测（依据响应头 Content-Type；检测结果为「无法判定」时不写入具体值，也不覆盖用户选择）。XML 与多行（NDJSON）互斥。
- **数据提取路径**：唯一定位「记录集合」的路径——JSON 用 JSONPath，XML 用 XPath；留空表示整个响应作为一条记录；数组需显式 `[*]` 才会展开为多条记录。
- **多行响应**：按行解析（NDJSON/每行一条记录）。
- **响应结构树**：基于原始响应构建，可点选节点自动填充提取路径（数组节点自动追加 `[*]`），并区分可选中与不可选中节点。
- **响应配置门禁**：为避免在未验证响应的情况下配置路径，响应类型、数据提取路径、多行响应在首次试跑成功后才可编辑；若试跑失败但无法判定响应格式，则解锁（防止死锁）；一旦解锁不再回锁。门禁不影响保存。
- **试跑回显**：展示响应头声明、判定结果、多行形态、本次使用格式、冲突/无法判定提示，并保留原始响应文本与解析结果供排查。

#### 2.4.3 详情补全（列表 → 详情两跳采集）

针对「列表接口只返回关键字段、需再逐条调用详情接口补全」的场景：

- **开关控制**；关闭时不发起任何详情请求，不产生详情阶段。
- **列表键值来源**：空或 `#this` 表示取记录本身（适用于标量数组）；也可指定字段名或 JSONPath。
- **键值占位符**：默认 `id`，在详情请求的 URL / 请求头 / 查询参数 / 请求体中通过 `${id}` 引用。
- **FORM 请求体的占位符**：正文按 `application/x-www-form-urlencoded` 编码串处理，替换前逐段解码，因此 `${id}` 原样书写或已被表单编码（如 `%24%7Bid%7D`）都能识别；注入的键/值按表单规则编码，其中的 `&`、`=`、`+`、`%` 不会破坏报文分隔。
- **详情请求**：URL、请求方法（GET/POST）、请求头、查询参数、请求体（NONE/JSON/FORM/XML）。
- **详情响应**：响应类型（JSON/XML）、详情数据路径（JSONPath/XPath，留空取整个响应）、并发数（默认 4，1–32）。
- **补全试跑**：输入样例键值，展示详情响应与合并结果（合并规则为顶层合并、同名字段详情覆盖列表）。
- **合并与容错**：详情对象与列表记录顶层合并后进入字段映射；单条详情失败时保留列表行继续写入（记为详情阶段失败样本，任务不因此失败）。
- **继承**：详情请求默认继承列表接口的认证与超时配置。

### 2.5 字段映射

字段映射归属采集任务（一个任务一套映射），描述「源记录字段 → 目标表字段」的转换与落库结构。

**功能点：**

1. **样例数据**：以任务关联接口配置的试跑结果作为样例；支持「刷新样例数据」（发起真实试跑）。
2. **映射行配置项**：
   - 源字段（点击或拖拽样例字段设置）；
   - 目标字段；
   - 目标类型：VARCHAR / STRING / BIGINT / DECIMAL / DATE / TIMESTAMP / BOOLEAN；
   - 长度（仅 VARCHAR 有效，范围 1–65535，默认 255）；
   - 主键（勾选表示该列为合并/冲突键）；
   - 可空（主键自动强制非空且锁定）；
   - 转换表达式（内置函数或自定义表达式）；
   - 关联状态、排序（上/下移动）、删除。
3. **类型规则**：
   - STRING 为长文本，不占用长度、不可作为主键；
   - VARCHAR 需要长度，仅 VARCHAR 使用长度；
   - 长度仅对 VARCHAR 生效，其他类型隐藏长度输入。
4. **内置转换函数**：trim、upper、lower、to_string、to_int、to_decimal、to_date；需填写裸函数名（如 `upper`），不支持 `upper()` 形式。
5. **主键语义**：主键是合并/冲突键的唯一来源；勾选主键即视为非空；自动建表时主键列生成 `PRIMARY KEY`，MERGE 写入时作为 Upsert 冲突键。
6. **自动生成映射**：
   - 存在目标表列时，按「样例字段 ↔ 目标列名」分级相似度匹配（精确 → 包含/分词 → 编辑距离阈值）生成映射到真实列；
   - 无目标表列时，按样例字段名生成；
   - 类型推断：字符串 → STRING、整数 → BIGINT、小数 → DECIMAL；
   - 自动生成为整表替换。
7. **目标字段选择模式**：
   - 自动建表开启：目标字段自由输入，类型/长度可编辑（用于生成建表语句）；
   - 自动建表关闭（已有表）：目标字段从目标真实列中选择，类型/长度只读，主键由目标表决定且只读；保存时校验所有目标字段均为合法列。
8. **MERGE 前置校验（非阻断提示）**：目标表无主键时提示「MERGE 将无法执行」；存在主键但主键列未被映射时提示「MERGE 可能无法生效」。
9. **映射预览**：可对样例数据执行映射与转换，预览「原始样例 → 转换后结果」（不写入业务库）。

### 2.6 采集任务管理

任务将「接口配置 + 目标数据源 + 字段映射 + 写入策略 + 调度策略」组合为一次可执行的采集作业。

**功能点：**

1. **任务列表**：展示任务名称、关联接口、目标数据源（`【类型】名称`）、目标表、写入模式、调度类型、状态；支持按名称模糊、数据源、写入模式、调度类型、状态筛选，分页。
2. **任务基本信息**：任务名称（必填、≤100 字符、全局唯一）、关联接口配置（可跳转查看/编辑）、目标数据源、目标库/模式、自动建表开关、目标表名、批量条数、写入模式、失败重试次数、执行超时、失败告警开关、调度策略、备注；保存前校验目标字段映射列表不能为空。
3. **自动建表与目标表**：
   - 开启：目标表名为自由输入（新表名）；
   - 关闭：目标表名从已存在表中选择，字段映射进入列选择模式。
4. **写入模式**：
   - INSERT（追加）：直接插入；
   - MERGE（合并）：按键值做 Upsert（自动建表开启时用映射主键；已有表时用目标表真实主键）；
   - TRUNCATE_INSERT（清空追加）：写入前清空目标表再插入。
5. **批量与容错**：批量条数（默认 500）；失败重试次数；执行超时（毫秒，0 表示不限）；失败告警开关。
6. **调度策略**：手动执行（MANUAL）/ 单次执行（ONCE）/ 定时执行（CRON，Cron 表达式，界面提供释义与语法参考）。
7. **立即执行**：手动触发一次采集，异步在后台执行并返回执行记录 ID，前端跳转到执行详情；同一任务已有「运行中」执行时拒绝重复触发。
8. **暂停/恢复**：定时任务可暂停、恢复（列表仅在 CRON 且对应状态下显示）。
9. **任务状态**：0 未启动 / 1 运行中 / 2 暂停。
10. **删除**：删除任务、其字段映射及该任务的执行记录（含执行阶段明细）并注销调度；**存在「运行中」执行的任务不允许删除**；不删除所引用的接口配置。
11. **任务与接口关系**：一个接口配置可被多个任务共享（N:1），任务删除不影响接口配置。

### 2.7 采集执行引擎

采集执行采用「分页流式」方式：逐页「读取 → （详情补全）→ 转换 → 写入」，处理完一页即释放，内存占用与单页/单批规模相关，而与总记录数无关。

**功能点：**

1. **流水线阶段**：READ（读取+解析）/ DETAIL（详情补全，启用时）/ TRANSFORM（字段映射+转换）/ WRITE（写入），完成后为 DONE。
2. **分页拉取**：按分页配置逐页请求；页与页之间可配置节流；达到终止条件后停止。
3. **认证与参数**：按认证配置生成认证头/查询参数/请求体字段，与用户配置的请求头、查询参数、请求体合并；分页参数支持占位符或固定键注入，已作为占位符出现的参数不重复注入；参数位置为 PATH 时优先替换 URL 路径中的 `${参数名}`，未占位的参数按查询参数追加。
4. **响应解析**：按响应类型分派 JSON（JSONPath）/ XML（XPath）/ NDJSON；将记录集合标准化为记录列表，供后续处理。
5. **数据转换**：
   - 字段映射模式：按映射提取并转换字段；
   - Groovy 脚本模式：脚本以上下文变量 `records`（当前页记录列表）、`log`、`json` 运行，须返回记录列表；
   - 转换按页执行（脚本仅能看到当前页记录）。
6. **写入**：
   - 自动建表：目标表不存在时按映射结构生成建表语句并创建（含主键、非空、长度、默认值）；
   - 批量写入：按批量条数分批入库，单批失败记为失败行并继续，不中断整体；
   - 写入会话：一次执行内复用同一目标连接；建表与清空（TRUNCATE_INSERT）只执行一次；
   - 部分写入：允许运行中途读取/转换失败时保留已写入页，不做整体回滚；转换失败导致任务标记为失败。
7. **重试与超时**：任务级失败重试与执行超时；每次尝试有独立执行记录。
8. **告警触发**：任务开启失败告警且执行失败时，按告警配置推送。
9. **统计口径**：记录采集总记录数、成功入库数、失败数、采集页数，以及各阶段输入/输出/成功/失败/耗时统计。

### 2.8 执行监控与可观测性

**功能点：**

1. **执行历史（主从双栏）**：左侧为任务列表（可搜索、分页，默认选中最新创建的任务），右侧为所选任务的执行记录（状态、总记录、成功、失败、耗时、采集页数、开始/结束时间），支持刷新与进入详情；左右分页相互独立。
2. **执行详情**：
   - 概要：执行 ID、任务 ID、状态、起止时间、耗时、总记录/成功/失败/页数、错误信息；
   - 运行中：显示当前阶段与已处理条数，并每 2 秒自动轮询刷新；
   - 分阶段明细：各阶段的输入、输出、成功、失败、耗时；
   - 失败样本：按阶段展示失败原因与源记录片段（默认每阶段最多 10 条）；
   - 入库数据预览：按目标表读取已入库数据（默认 100 条，最多 1000 条）。
3. **执行状态**：RUNNING / SUCCESS / FAILED / PARTIAL（部分成功）。
4. **执行记录查询**：支持按任务、状态、分页查询执行记录。

### 2.9 告警配置

**功能点：**

1. **告警开关**：开启后采集失败时按配置推送。
2. **推送配置**：推送地址、Content-Type、请求体模板。
3. **模板变量**：请求体模板支持 `${变量}` 替换，内置变量包括：`${taskName}`、`${taskId}`、`${apiConfigId}`、`${datasourceId}`、`${exception}`、`${exceptionType}`、`${accessTime}`。
4. **测试推送**：使用示例数据模型发起真实推送测试。
5. **示例数据模型**：提供示例变量取值供参考。
6. **容错**：告警推送失败仅记录日志，不影响采集主流程。

### 2.10 仪表盘

**功能点：**

1. **统计卡片**：接口配置数、数据源数、采集任务数、执行成功率。
2. **图表**：近 7 天执行趋势（成功/失败）、执行结果分布（成功/失败/运行中/部分成功）。
3. **近期执行**：展示最近 10 条执行记录，并提供进入完整执行历史的入口。

### 2.11 通用前端交互

1. **导航与菜单**：仪表盘、数据源管理、接口管理（认证配置 / 接口配置）、任务管理（采集任务 / 执行监控）、告警配置、用户管理（仅管理员）。
2. **会话与鉴权**：令牌随请求自动携带；令牌失效时自动清理登录态并跳转登录页；用户管理菜单与路由仅对管理员可见。
3. **列表通用能力**：分页、筛选、查询/重置、删除二次确认。
4. **键值编辑器**：统一的键值对编辑组件，空键自动忽略，请求头提供预设一键添加。
5. **响应结构浏览**：点选节点填充路径，原始/格式化视图切换。
6. **界面规范**：统一品牌色、系统字体、设计令牌；保持可访问性（焦点可见、键盘可操作）。

## 三、系统架构（含技术栈）

### 3.1 总体架构

系统采用「前后端分离 + 分层单体」架构：

```
┌─────────────────────────────────────────────────────────────┐
│              Vue 2 + Element UI 前端（管理控制台）             │
│  仪表盘 | 数据源 | 认证配置 | 接口配置 | 采集任务 | 监控 | 告警 │
└───────────────────────────┬─────────────────────────────────┘
                            │ REST API (JSON)
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                  Spring Boot 后端（单体应用）                  │
│                                                             │
│   接入层：REST 控制器（统一响应体 / 统一异常处理 / 鉴权拦截）    │
│   业务层：数据源、认证、接口、任务、执行、告警、用户 服务         │
│   引擎层：采集流水线（读取 → 详情补全 → 转换 → 写入）           │
│   调度层：Quartz 定时调度                                      │
│   持久化：MyBatis（元数据库访问） + 动态目标数据源管理           │
│                                                             │
│  元数据库（MySQL）：接口/数据源/认证/任务/映射/执行/告警/用户     │
└───────────────┬───────────────────────────┬─────────────────┘
                │                           │
                ▼                           ▼
     外部 REST API（HTTP/HTTPS）     目标数据库（动态数据源连接池）
```

### 3.2 模块划分

| 模块 | 职责 |
|------|------|
| apigrab-common | 公共能力：统一响应体与分页结果、异常体系与错误码、通用工具 |
| apigrab-persistence | 持久化层：实体、枚举、MyBatis 映射与 DAO，元数据库访问 |
| apigrab-core | 核心采集引擎：HTTP 调用、响应解析、认证、数据映射与转换、动态数据源管理、写入、告警 |
| apigrab-admin | 管理后台与应用入口：REST 控制器、业务服务、Quartz 调度、Flyway 迁移、应用配置 |
| apigrab-web-ui | 前端管理界面（Vue 2 + Element UI），独立于 Maven 构建 |

模块依赖方向：admin → core → persistence → common。

### 3.3 采集流水线架构

- **读取（READ）**：按接口配置发起 HTTP 请求（含认证、超时、分页、参数注入），获取响应并解析出记录集合。
- **详情补全（DETAIL，可选）**：逐条调用详情接口，按键值把详情对象合并到列表记录。
- **转换（TRANSFORM）**：按字段映射与转换函数（或 Groovy 脚本）生成目标结构。
- **写入（WRITE）**：按写入模式、批量条数、自动建表策略写入目标库。

流水线按页调度，页内完成「读取→补全→转换→写入」闭环，实现流式处理。

### 3.4 动态数据源与调度

- **动态数据源**：目标库连接池在运行期按需创建、缓存、失效与重建，与元数据库分离；支持导出驱动类与 JDBC URL 模板。
- **外部驱动**：国产库驱动按 `drivers/<类型名小写>/<版本>/*.jar` 放置，由 `DriverCatalog` 扫描、`URLClassLoader` 隔离加载；Hikari 通过 `ExternalDriverDataSource` 使用，不经 `DriverManager` 全局注册。
- **方言族**：`SqlDialectStrategy` 按兼容族复用——达梦复用 Oracle 方言，人大金仓 / 神通 / 瀚高 / openGauss / 优炫复用 PostgreSQL 方言，GBase8A / OceanBase 复用 MySQL 方言；差异点（探活、元数据查询、长文本与布尔类型、预览分页）由各子类覆盖。
- **任务调度**：基于 Quartz，调度信息持久化于元数据库（JDBC Job Store，支持集群）；定时任务按 Cron 触发，手动执行以异步后台方式运行。

### 3.6 关键设计约定

1. **统一响应与异常**：接口统一返回 `{code, message, data}` 结构；业务异常按语义映射到 HTTP 状态码（400/401/403/404/405 等），非标准错误码回落 500。
2. **命名唯一性**：接口配置、采集任务、数据源、系统用户名称/用户名全局唯一，忽略大小写与首尾空格；唯一性由服务层校验并以数据库唯一索引兜底。
3. **枚举约定**：
   - 编码型枚举（状态类）以整型编码存储与传输（如任务状态 0/1/2，启用状态 0/1）；
   - 字符型枚举按名称存储与传输（如请求方法、请求体类型、认证类型、写入模式、调度类型等）。
4. **JSON 字段类型化**：请求头/查询参数、分页配置、详情补全配置、认证内容、样例数据、失败样本等以结构化对象持久化。
5. **安全边界**：认证/鉴权统一在接入层拦截；密码哈希存储、源库密码加密存储；配置中的敏感值在界面按需遮蔽。

## 四、遗留项

以下为当前已知的遗留或待改进事项（不阻断主要功能，供后续迭代参考）：

1. **编辑页未保存离开提醒**：编辑类页面尚未实现离开前未保存提醒。
2. **大响应/极端数据**：超大响应与极端数据量场景下的边界体验仍需持续验证。
3. **自定义 Content-Type 头重复**：自定义请求头与内置头可能重复而非覆盖。
4. **XML 请求体预校验缺失**：XML 请求体未做发送前预校验；分页注入失败时仅在日志体现，界面无提示。
5. **真实库行为验证**：外键约束、引用计数、迁移等在真实数据库上的行为尚需集成验证；XML/FORM 与真实接口的联调需人工确认。
6. **窄屏适配**：仪表盘指标卡片等区域在窄屏下的重排适配尚不完善。
7. **PATH 分页不做 URL 编码**：路径占位符按原始值替换；若游标等取值包含 `/`、`?`、`#` 等路径保留字符，需在初始游标或接口侧使用已编码的值。
